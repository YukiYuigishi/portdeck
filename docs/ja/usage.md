# 使い方

portdeckの接続先選択、SSHセッション、保存済み転送ルールの操作方法を説明します。設定ファイルとControlPathについては[実行環境と設定](runtime-and-configuration.md)、問題の調査方法については[トラブルシューティング](troubleshooting.md)を参照してください。

## 接続先の検出

portdeckは`~/.ssh/config`と再帰的な`Include`から、具体的な`Host`エイリアスを収集します。`Host *`、ワイルドカード、否定パターンは候補として表示しません。ただし、それらの設定は`ssh -G <alias>`による設定解決と実際の接続時にOpenSSHが通常どおり適用します。

portdeckはHostName、User、Port、ProxyJumpなどの意味を独自に解釈せず、SSH設定ファイルも変更しません。

## キーボード操作

通常画面では次のキーを使います。

| キー | 操作 |
| --- | --- |
| `Tab` | TargetsとForwardsのペインを切り替える |
| `h` / `←` | Targetsペインへ移動する |
| `l` / `→` | Forwardsペインへ移動する |
| `↑` / `↓` / `j` / `k` | 選択を移動する |
| `/` | Hostエイリアスの検索を開始する |
| `c` | 選択した接続先へ接続する |
| `r` | `ssh -O check`で接続状態を再確認する |
| `a` | 転送ルールを追加して保存する |
| `e` | 選択したInactiveな転送ルールを編集する |
| `Space` | 選択した転送を有効化、または取消する |
| `D` | 転送ルールを確認後に削除する |
| `d` | SSHセッションを確認後に終了する |
| `E` | 直近のOpenSSH stderrまたは起動診断を表示する |
| `q` / `Ctrl-C` | portdeck所有セッションを終了してquitする |

確認画面では`y`または`Enter`で実行し、`n`または`Esc`で取り消します。エラー詳細は`E`、`Enter`、`Esc`のいずれかで閉じられます。

## 接続先の検索

`/`を押すと、Hostエイリアスの部分一致検索を開始します。検索では大文字と小文字を区別しません。

- 文字入力: 検索語を編集
- `Backspace`: 末尾の文字を削除
- `Enter`: 現在の絞り込みを確定
- `Esc`: 編集前の絞り込みへ戻る

空の検索を確定すると全接続先を再表示します。検索結果から接続や状態確認を行っても、画面上の行ではなく対応する接続先が正しく操作されます。検索はSSH設定やportdeckの保存設定を変更しません。

## SSHセッションの操作

Targetsペインで接続先を選び、`c`を押すとportdeck専用のOpenSSH ControlMasterを開始します。認証、鍵のパスフレーズ、初回ホスト鍵確認などで対話が必要な間はTUIを一時停止し、OpenSSHが端末を直接使える状態にします。OpenSSHの処理が終わるとTUIを再描画して戻ります。

`r`を押すと`ssh -O check`で現在のControlMasterを確認します。切断を検出した場合、そのセッション配下の転送は`Unavailable`として表示されます。自動再接続は行いません。

`d`を押して確認すると、選択したセッションを`ssh -O exit`で終了します。その配下の転送も利用できなくなります。

`q`または`Ctrl-C`で終了すると、portdeckが所有する全ControlMasterを明示的に停止します。TUIを閉じた後も接続を維持するdetach機能はありません。

## 転送ルールの追加

`a`を押すと転送ルールの入力フォームを開きます。`Tab`または`↓`で次の項目、`Shift-Tab`または`↑`で前の項目へ移動し、`Enter`で保存します。`Esc`は入力を破棄します。

先頭のForward kindは`←`／`→`または`Space`で切り替え、`l`でLocal、`s`でSOCKSを直接選択できます。

### Local転送

OpenSSHの`-L`に相当します。

- Label: 任意の表示名
- Local bind address: 既定値`127.0.0.1`
- Preferred local port: 空欄ならリモート宛先ポートと同じ番号
- Remote destination host: リモート側から見た宛先。既定値`127.0.0.1`
- Remote destination port: 必須。1から65535

### SOCKS転送

OpenSSHの`-D`に相当するSOCKS4/5 listenerです。SOCKS処理とTCP中継はOpenSSHが行います。

- Label: 任意の表示名
- Local bind address: 既定値`127.0.0.1`
- Preferred local port: 既定値`1080`。1から65535

SOCKSではリモート宛先hostとportを指定しません。アプリケーション側でSOCKS proxyを実装したり、認証を追加したりはしません。

## 転送ルールの編集

ForwardsペインでInactiveな保存済みルールを選び、`e`を押すと追加時と同じフォームで編集できます。`Enter`で保存し、`Esc`で変更を破棄します。

編集してもルールID、所属する接続先、一覧上の選択位置は変わりません。また、編集後に自動で有効化されることもありません。

Active、Adding、Removing、Unavailable、Failedのルールや、実際のローカルポート情報が残っているルールは編集できません。先に`Space`で転送を取り消してInactiveへ戻してください。

## 転送の有効化、取消、削除

ルールを保存しただけでは転送は有効になりません。SSHセッションへ接続した後、Forwardsペインでルールを選んで`Space`を押してください。

希望したローカルポートが競合する場合、最大20個の連続した候補を試します。事前のbind確認だけでは成功とみなさず、OpenSSHが実際に転送を追加できた場合だけ`Active`と表示し、確保したローカルポートを示します。

Activeな転送で`Space`を押すと、追加時と同じ正規化済み指定を使ってOpenSSHへ取消を依頼します。取消に失敗した場合、UI上だけ成功したようには扱いません。

Inactiveなルールを設定から削除するには`D`を押し、対象を確認してから実行します。Activeなルールは先に取り消してください。

## 外部公開listener

bind addressに`0.0.0.0`、`::`、`*`を指定すると、ローカルネットワークなどからlistenerへ接続できる可能性があります。portdeckは保存前に追加確認を表示します。

SOCKS listenerにはportdeck独自の認証がありません。外部公開すると、接続可能な利用者がSSH経由で任意の宛先へ通信できるため、bind先とアクセス可能なネットワークを確認してください。

追加後に外部公開bindへ編集する場合も同じ確認を表示します。既定値はループバックの`127.0.0.1`であり、portdeckが暗黙に外部公開することはありません。
